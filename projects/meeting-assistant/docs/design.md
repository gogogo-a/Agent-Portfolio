# 会议预约 · 详细设计

## 核心想法

平台画布不能画成圈。对话里用户每说一句，整张图会从头跑一遍，所以：

> 循环靠多轮对话完成；画布本身是直线；用会话变量记住草稿、校验结果和当前在等什么。

## 节点怎么分层

| 层 | 放什么 | 不放什么 |
|----|--------|----------|
| 大模型 | 意图、槽位、核对单 | 连着调好几个接口 |
| 代码 | 解析结果、状态机只出下一步、上班时段、拼回复 | 一个节点里串很多接口 |
| 接口 | 一个节点一个接口 | 多个接口揉在一个代码节点 |
| 分支 | 按下一步分流 | 只在代码里分支、画布上看不出来 |
| 赋值 | 写回会话变量 | — |

## 状态机大概逻辑

源码见 `src/code_state_machine.py`：

```text
若在等改口 → 改口引导
若在抢会议室 → 抢会议室
老师未锁定:
  有姓名 → 有时间就查重名，没有时间就只查老师
  无姓名 → 追问参会老师
老师已锁定:
  无时间 → 展示空闲表
  有时间 → 继续预约
```

## 画布怎么排

```python
def pos(col, row):
    return col * 380, row * 170
```

- 主流程一行，接口链一行，出口一行
- 连线要分清从哪个出口出去
- 分支用一个节点里的多条件，不要纵向串一长串单条件判断

## 提示词

意图、槽位等要固定结构输出时：写清角色、任务、背景、输入、限制、输出格式、例子、怎样算好；温度调低；后面接解析代码。
